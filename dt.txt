RBAC Architecture
User
 │
 ├── UserOrganization
 │       │
 │       ▼
 │      Role (Admin, Owner etc)
 │       │
 │       ▼
 │  RolePermission (with Role_id find out the relevant permission IDs)
 │       │
 │       ▼
 │   Permission (Using permission Ids find the relevant permissions)
 │
 └── UserProject
         │
         ▼
        Role (Engineer, QA ETC)
         │
         ▼
    RolePermission (with Role_id find out the relevant permission IDs)
         │
         ▼
     Permission (Using permission Ids find the relevant permissions)


Adding a new user only inserts into UserOrganization or UserProject.
Changing a user's role only updates the role_id in those tables.
Adding a new permission only updates the global RolePermission table.
No duplication of roles or permissions across organizations.

SQL QUERY TO GET OWNER AND ADMINISTRATOR DETAILS FOR Organization USER
SELECT
    o.id   AS organization_id,
    o.name AS organization_name,
    u.id   AS user_id,
    u.name AS user_name,
    u.email,
    r.name AS role
FROM app.organization o
JOIN app.user_organization uo
    ON uo.organization_id = o.id
JOIN app."user" u
    ON u.id = uo.user_id
JOIN app.role r
    ON r.id = uo.role_id
WHERE r.name IN ('Owner', 'Administrator')
ORDER BY
    o.name,
    CASE
        WHEN r.name = 'Owner' THEN 1
        ELSE 2
    END,
    u.name;


SQL QUERY TO GET Project Owner DETAILS FOR project USER
SELECT
    p.id   AS project_id,
    p.name AS project_name,
    u.id   AS user_id,
    u.name AS user_name,
    u.email,
    r.name AS role
FROM app.project p
JOIN app.user_project up
    ON up.project_id = p.id
JOIN app."user" u
    ON u.id = up.user_id
JOIN app.role r
    ON r.id = up.role_id
WHERE r.name IN ('Project Owner', 'Project Administrator')
ORDER BY
    p.name,
    CASE
        WHEN r.name = 'Project Owner' THEN 1
        ELSE 2
    END,
    u.name;
